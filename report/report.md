# СР1
## 1. Описание задачи и данных
**Задача:** Бинарная классификация транзакций (фрод / не фрод).
**Данные:** Digital Payment Fraud Detection Benchmark (Kaggle). Исходный объем — около 400 000 записей. В данных присутствует сильный дисбаланс классов: доля мошеннических операций составляет всего 1.62%. В связи с этим в качестве главных целевых метрик выбраны **PR-AUC** и **F1-score**, а не Accuracy.

В ходе первичного анализа была обнаружена и удалена колонка `post_auth_risk_score`, которая содержала информацию о будущем (target leakage).

## 2. Подготовка данных и сплит
Поскольку паттерны мошенничества меняются со временем (temporal drift), случайное перемешивание данных привело бы к утечке (Data Leakage). Был применен **строгий сплит по времени**:
* **Train:** Январь — Август (240 090 строк)
* **Validation:** Август — Сентябрь (60 023 строки)
* **Test:** Октябрь — Декабрь (99 887 строк)

Для базовой модели категориальные признаки были закодированы методом One-Hot Encoding (`drop_first=True`), а числовые отмасштабированы с помощью `StandardScaler`.

## 3. Baseline модель и результаты
В качестве базовой модели "из коробки" была обучена **Логистическая регрессия**. Для борьбы с дисбалансом классов использован гиперпараметр `class_weight='balanced'`.

**Результаты на валидационной выборке:**

| Метрика | Значение |
|---------|----------|
| **PR-AUC** | **0.3316** |
| ROC-AUC | 0.8428 |
| F1-score | 0.1251 |
| Recall | 0.7585 |
| Precision | 0.0682 |

**Вывод по Baseline:**
Модель успешно улавливает мошенников (высокий Recall — найдено 870 из 1147 фродовых транзакций), однако цена этого — огромное количество ложных срабатываний (почти 12 тысяч честных операций отмечены как фрод, Precision 6.8%). 

Линейная модель недостаточно хорошо разделяет сложные нелинейные зависимости. Для повышения Precision и итоговой метрики PR-AUC на следующем этапе будут применены ансамбли деревьев (Random Forest, XGBoost, LightGBM) и методы Feature Engineering.
